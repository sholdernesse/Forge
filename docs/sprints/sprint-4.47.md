# Sprint 4.47 — Four-Week Starting Block

## Outcome

An approved Forge setup now becomes visible multi-week direction. The Training Week panel shows where the user is in a simple four-week foundation block and explains how the current phase supports the primary goal.

## Delivered

- Added a four-week Learn/Calibrate, Repeat, Progress, and Review sequence.
- Derives the current week from the approved-plan timestamp without adding stored state.
- Adapts the block purpose to the selected primary goal.
- Uses more compact calibration language for experienced users and educational language for newer users.
- Keeps load and repetition progression behind repeatable movement quality.
- Shows completed, current, and upcoming phases in the existing Training Week panel.
- Adds a two-column phone layout that remains readable without widening the dashboard.
- Added focused coverage for phase calculation, progression safeguards, experience language, and the four-week boundary.

## Boundaries

- This is a visible starting-block contract, not a second workout generator.
- Daily readiness, feedback, schedule intent, and deload policies continue to control the actual session.
- The block adds no route, modal, service, storage schema, or navigation item.
- Plan-level progression across later mesocycles remains Phase C work.

## Acceptance

- A user can identify their current block phase and the reason for it within the Training context.
- The four phases fit the existing desktop and phone composition.
- Progression language never rewards load increases ahead of controlled movement.
- Users without an approved onboarding profile do not see fabricated block progress.
- Type checks, focused tests, the full suite, and the production web build pass.
